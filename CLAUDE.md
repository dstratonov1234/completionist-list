# Completionist List — инструкция для Claude

Личный трекер **закрытия игр** пользователя на GitHub Pages. Пользователь пишет в чате по-русски. Когда он начинает игру, он присылает файл **«условия закрытия»** (`УСЛОВИЯ_ЗАКРЫТИЯ.md`). Это его собственный нумерованный список целей, после которых игра считается закрытой навсегда. По ходу игры и в конце он присылает **отчёты** — свободный текст без формата. Отчёты на сайт **не идут**: по ним Claude сам отмечает выполненные условия. Задача Claude — вести эти данные, иллюстрировать каждую цель и оформлять каждую игру **своим уникальным UI/UX/VFX**. Изменения публикуются сразу.

- Сайт: https://dstratonov1234.github.io/completionist-list/
- Репозиторий: https://github.com/dstratonov1234/completionist-list

## Главная

Тёмная и чистая — только поиск и список, без заголовка, статистики и вкладок. Список сверху вниз в сворачиваемых категориях «Закрытые» → «В процессе» → «В планах», внутри — по алфавиту. У каждой игры — свой баннер в стиле игры. При наведении фон главной становится стартовым кадром страницы этой игры, а клик — бесшовный переход: главная растворяется, начинается страница игры с её заставкой.

## Что показывать, а что нет

Страница игры — **только про условия закрытия** (без брифинга, «цели закрытия», настроек прохождения и «точки закрытия»): какие цели выполнены, допинформация к ним (картинка, что дало, как засчитано, короткие подробности из отчётов, чек-листы) и прогресс. Сами отчёты не показываются.

**Статус игры** («закрыта», «в процессе», «в планах», место в очереди) нигде на сайте не называть, кроме названия категории в списке на главной: он и так виден по числу выполненных условий. В темах вместо статуса — прогресс по условиям («Выполнено условий: 3 из 8»). **Даты** (начала, закрытия, добавления, выполнения целей) на сайте не показывать нигде.

**Не показывать** информацию «об игре»: описание, жанры и теги, разработчика, год, оценку, списки всех боссов и достижений, галереи скриншотов. Пользователь прямо сказал, что это ему не нужно. Арт игры (обложка, баннер, логотип) нужен только для оформления.

## Демо-игры

Сейчас в списке семь пробных игр с `"demo": true`: Hollow Knight, Celeste, Elden Ring, Cyberpunk 2077, Silksong, Zelda TotK и Fire Emblem Engage. Пользователь попросил их, чтобы посмотреть, как работает сайт. Условия закрытия у первых шести выдуманы для примера; у Fire Emblem Engage — настоящий файл пользователя (`D:\FireEmblemEngage\УСЛОВИЯ_ЗАКРЫТИЯ.md`), прогресс 0, ничего не засчитывать без его отчётов. На странице такой игры в шапке стоит метка «демо».

Когда пользователь пришлёт первую настоящую игру, нужно удалить все игры с `demo: true` вместе с `data/conditions/<id>.json` и `themes/<id>/`, если только он не попросил оставить. Оформление удаляемой темы можно сначала перенести, если настоящая игра совпадает с демо.

## Структура

| Путь | Что это |
|---|---|
| `data/games.json` | Список игр: поле `updated` и массив `games` (только то, что нужно баннеру и шапке) |
| `data/conditions/<id>.json` | Условия закрытия игры: группы, цели, статусы, картинки и заметки к целям |
| `themes/<id>/` | Уникальное оформление игры: `theme.css`, `theme.js`, `assets.json`, `assets/` — см. `themes/README.md` |
| `index.html`, `assets/` | Сайт без сборки: список (`#/<вкладка>`) и страница игры (`#/game/<id>`); `assets/fx.js` — частицы |
| `scripts/import-conditions.js` | Импорт файла условий пользователя в `data/conditions/<id>.json` |
| `scripts/steam.js` | Поиск игры в Steam и арт для оформления (обложка, баннер, логотип) |
| `scripts/wiki.js` | Картинки и ссылки со статей вики — для иллюстраций к целям |
| `scripts/gen-image.py` | Генерация ассетов темы через OpenAI Images |
| `scripts/palette.py`, `scripts/fonts.js` | Палитра из арта и контраст; шрифты Google Fonts с кириллицей |
| `scripts/validate.js` | Проверка данных и тем; `--fix` пересчитывает счётчики целей, `--check-images` проверяет картинки и шрифты |

## Данные

### `data/games.json`

```json
{
  "id": "fire-emblem-engage",
  "title": "Fire Emblem Engage",
  "status": "in_progress",
  "started": "2026-10-15",
  "finished": "2026-12-01",
  "playtime": 80,
  "priority": 1,
  "added": "2026-10-10",
  "notes": "Короткая заметка пользователя",
  "aliases": ["FE Engage"],
  "steamAppId": 367520,
  "cover": "https://…", "hero": "https://…", "logo": "https://…",
  "goals": { "done": 12, "total": 30 },
  "theme": { "…": "см. «Оформление»" }
}
```

- Обязательные поля: `id` (kebab-case латиницей), `title` (оригинальное название), `status` (`completed`, `in_progress` или `planned`). Статуса «брошено» нет: пользователь игры не бросает.
- Даты пишутся как `YYYY-MM-DD`, допустимы `YYYY-MM` и `YYYY`. «Сегодня» — это текущая дата сессии. Даты (`started`, `finished`, `added`, `date` у целей) хранятся только как запись в данных — на сайте их нет.
- `playtime` указывать, только если пользователь сам назвал часы. `priority` — место в очереди планов.
- `goals` — счётчик выполненных условий для баннера. Руками не править: его пересчитывает `node scripts/validate.js --fix`.

### `data/conditions/<id>.json`

Создаётся импортом файла пользователя, затем дополняется иллюстрациями:

```json
{
  "title": "Окончательное закрытие Fire Emblem Engage",
  "groups": [
    {
      "title": "Сюжет",
      "note": "необязательная подпись группы",
      "goals": [
        {
          "n": 1,
          "title": "Основной сюжет: Prologue → Chapter 26",
          "gives": "Что нового даёт", "needs": "Что потребуется", "unlock": "Открывается", "counts": "Как засчитываем",
          "extra": [{ "label": "Другая колонка", "value": "…" }],
          "done": true, "date": "2026-11-30",
          "image": "https://…", "link": "https://…",
          "note": "Короткая фраза пользователя об этой цели (из отчёта/чата), если она того стоит",
          "details": "Допинформация о том, как именно это было",
          "gallery": ["https://…"],
          "checklist": [{ "label": "Базовые", "items": [{ "title": "Lodestar Rush (Marth)", "done": true }] }]
        }
      ]
    }
  ]
}
```

## Что делать на сообщения пользователя

- **Начинает игру и присылает условия закрытия** (путь к `.md` или текст):
  1. `node scripts/import-conditions.js "<файл>" <id>` (если прислан текст — сначала сохранить его в scratchpad). Импорт берёт только группы и цели из «Конечного списка» (таблицы и чек-листы). Шапка файла («Цель», раздел «Игра», редакция) и остальные разделы («Точка закрытия», «Сознательно не делаем», «Источники»…) на сайт не идут: они только мусорили бы страницу, а игра закрыта, когда выполнены все условия.
  2. Запись в `games.json`: `status: in_progress`, `started`, арт для оформления (`node scripts/steam.js search` → `info <appid>` → взять только `steamAppId`, `cover`, `hero`, `logo`; не из Steam — Википедия или вики игры, см. ниже).
  3. Каждой цели — картинку и ссылку (раздел «Иллюстрации к целям»).
  4. Уникальное оформление игры (раздел «Оформление»).
  5. `node scripts/validate.js --fix --check-images`, коммит, push.
- **«Выполнил #N» / «прошёл паралог X»** → у цели `done: true`, `date`; слова пользователя о ней — в `note`; подробности — в `details`. Если отмечен пункт чек-листа — `done` у пункта.
- **Прислал новую редакцию файла** (или файл с отметками ☑) → повторить импорт тем же `id`. Тексты и статусы обновятся, а картинки, ссылки, даты и заметки сохранятся. Импорт молча не снимает уже стоящие отметки.
- **Отчёт (промежуточный или финальный)** → разобрать по разделу «Отчёты»: отметить выполненные условия и пункты чек-листов, даты, подробности. Если по финальному отчёту закрыты все условия — `status: completed`, `finished`, `playtime` (если назван); если чего-то не хватает — уточнить у пользователя.
- **«Планирую X»** → `status: planned`, `added`, `priority`. Условия появятся, когда он пришлёт файл; до этого — только баннер с артом и оформлением.

Если игра уже есть — обновлять её, а не создавать новую. Ничего не засчитывать и не удалять из условий молча: список меняется только по прямому слову пользователя.

## Иллюстрации к целям

Каждая цель должна выглядеть как награда, а не как строка таблицы: нужны картинка, ссылка и, когда есть, детали.

- **Вики игры**: `node scripts/wiki.js <вики> "Статья 1" "Статья 2" …` даёт `image` и `link`. Если главная картинка статьи не подходит — `--images "<статья>"`. Для Fire Emblem это `fireemblemwiki.org/w`, для многих игр — `<игра>.fandom.com`. `*.wiki.gg` отвечает 401 на запросы скриптов: их не использовать.
- **Википедия**: `node scripts/wiki.js en.wikipedia.org/w --images "<статья>"`.
- **Steam** (арт, скриншоты, иконки достижений) — когда цель про то, что видно на скриншоте, или прямо про достижение.
- **Проверка**:
  - Скрипты проверяют, что по ссылке картинка, но не проверяют, та ли это картинка. Поле `query` в выводе `wiki.js` значит, что статья найдена поиском и может быть не той.
  - Сомнительные картинки смотреть глазами: собрать контактный лист PIL-ом в scratchpad и открыть Read.
  - Предупреждение валидатора «та же картинка, что у …» почти всегда означает заглушку вики.
- Ссылки — только прямые http(s) на файлы с CDN: `shared.akamai.steamstatic.com`, `static.wikia.nocookie.net`, `upload.wikimedia.org` и т.п. В `index.html` стоит `<meta name="referrer" content="no-referrer">` — без него Fandom отдаёт заглушку. Не удалять.

## Оформление: уникальный UI/UX/VFX для каждой игры

У каждой игры своё оформление, а не перекраска общего шаблона: своя раскладка условий закрытия, свой интерактив, свои эффекты, свой «вход» на страницу, свой баннер на главной. Эталон — `themes/hollow-knight/`: Дневник охотника вместо списка целей, сосуд души вместо кольца прогресса, светомуха-курсор, заставка области. API модулей и обязательные правила — в `themes/README.md`.

Порядок работы:

1. **Понять эстетику игры**: как выглядят её меню, журнал, инвентарь, карта, шрифты. Посмотреть `hero`, `logo` и скриншоты: скачать в scratchpad и открыть Read.
2. **Токены `theme` в `games.json`** — база для баннера и страницы:
   - Цвета `bg`, `surface`, `text`, `accent`, `accent2`. Палитру даёт `python -P scripts/palette.py <hero> <cover>`. Контраст текста ≥ 4.5, проверять через `--contrast`.
   - Шрифты Google Fonts в `fonts`, `displayFont`, `headingFont`, `bodyFont`. Для русского текста — только шрифты с кириллицей: `node scripts/fonts.js check` и `node scripts/fonts.js list --cyrillic`.
   - Остальное: `radius`, `ornament`, `particles` (embers, sparks, ash, snow, rain, spores, dust, stars, petals, leaves, bubbles), `textures` (vignette, grain, scanlines, glow, fog, paper, halftone), `heroPosition`.
   - `css: true` и `js: true` включают `themes/<id>/theme.css` и `themes/<id>/theme.js`.
3. **Модуль `themes/<id>/theme.js`**:
   - Раскладка условий в духе игры: журнал, инвентарь, карта восхождения, лог заданий, гобелен и т.п.
   - Индикатор прогресса в стиле игры.
   - Фирменный эффект: курсор, свет или частицы.
   - Заставка при входе на страницу.
4. **`themes/<id>/theme.css`**: стили модуля и баннера на главной (`.gbanner[data-game="<id>"]`). Баннер — визитка игры: рамка, типографика, прогресс в стиле игры, эффект при наведении. Если у страницы игры что-то постоянно видно с самого начала поверх баннер-арта — повторить это на `.stage-layer[data-game="<id>"]`, чтобы вход с главной был бесшовным (см. `themes/README.md`). Заставки игр при входе (тучи, пиксели, занавески…) пользователь любит — их сохранять.
5. **Ассеты**: 3–6 оригинальных элементов (рамки, орнаменты, разделители, фоны, текстуры). Промпты записывать в `themes/<id>/assets.json`, генерировать командой `python -P scripts/gen-image.py --manifest themes/<id>/assets.json`. Без логотипов, текста и персонажей игры. Каждый ассет посмотреть глазами.
   - Ключ OpenAI — только из переменной окружения `OPENAI_API_KEY` или из файла вне репозитория (`--key-file`). Никогда не класть его в репозиторий: он публичный, а `.gitignore` закрывает только `*.key` и `.env*`. Если ключа нет — попросить у пользователя.
6. **Проверка в браузере**:
   - Баннер на главной, фон при наведении, вход в игру по клику и обратно, страница игры; десктоп и 375 px.
   - Клавиатура, `prefers-reduced-motion`, переход на другую игру и обратно (ничего не должно «протекать»), консоль без ошибок.
   - Модуль должен работать с любым набором целей: пустым, без картинок, с чек-листами, при любом статусе игры. Статус игры и даты модуль не выводит.

## Отчёты

Пользователь присылает отчёты — промежуточные или финальный — **обычным текстом без всякого формата**. Отчёт **не публикуется** и в репозитории не хранится (репозиторий публичный): это материал для Claude, чтобы закрывать условия.

Что делать с отчётом:

1. Сопоставить написанное с условиями закрытия этой игры (`data/conditions/<id>.json`): какие цели и пункты чек-листов теперь выполнены. Названия у пользователя могут быть неточными, по-русски или сокращённо — сопоставлять по смыслу.
2. Выполненным целям — `done: true` и `date` (из отчёта; если дата не названа — дата отчёта). Пунктам чек-листов — `done: true`.
3. Допинформация к целям — коротко, своими словами, без пересказа отчёта целиком: `details` (как именно закрыто: на какой сложности, с какой попытки, чем запомнилось), `note` (одна меткая фраза пользователя, если она того стоит), `gallery` (картинки к этому моменту, если он описал что-то конкретное — найти через вики).
4. Что засчитывать, решает формулировка «Как засчитываем» в условии. Если из отчёта неясно, выполнено ли условие, — не отмечать молча, а спросить. Ничего не засчитывать «по догадке» и не удалять из условий.
5. В ответе коротко перечислить, что отмечено (номера и названия) и что осталось.

## Публикация

После каждого обновления коммит и push в `main` делаются сразу, без вопроса: пользователь попросил держать сайт актуальным.

1. Обновить `updated` в `data/games.json`.
2. `node scripts/validate.js --fix --check-images` — должно быть `✓ OK`.
3. Коммит на русском: `Начато: Fire Emblem Engage (30 условий)`, `Fire Emblem Engage: выполнено #4–#6`, `Закрыто: Fire Emblem Engage`.
4. `git push`. GitHub Pages обновится примерно за минуту.
5. Коротко ответить пользователю: что изменилось и ссылка `https://dstratonov1234.github.io/completionist-list/#/game/<id>` (к конкретной цели — `…#/game/<id>` и номер цели).

## Локальный просмотр

`python -m http.server 8765` в корне репозитория (или конфигурация `site` в `.claude/launch.json`) и открыть http://localhost:8765. Открывать `index.html` напрямую как файл нельзя: `fetch` не работает с `file://`.
