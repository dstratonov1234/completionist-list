# Completionist List — инструкция для Claude

Личный трекер **закрытия игр** пользователя на GitHub Pages. Пользователь пишет в чате по-русски. Когда он начинает игру, он присылает файл **«условия закрытия»** (`УСЛОВИЯ_ЗАКРЫТИЯ.md`). Это его собственный нумерованный список целей, после которых игра считается закрытой навсегда. По ходу игры он сообщает, что выполнил, а в конце присылает отчёт обо всём. Задача Claude — вести эти данные, иллюстрировать каждую цель и оформлять каждую игру **своим уникальным UI/UX/VFX**. Изменения публикуются сразу.

- Сайт: https://dstratonov1234.github.io/completionist-list/
- Репозиторий: https://github.com/dstratonov1234/completionist-list

## Что показывать, а что нет

Страница игры — **только про условия закрытия**: какие цели выполнены, допинформация к ним (картинка, что дало, как засчитано, дата, комментарий пользователя, чек-листы), прогресс и итоговый отчёт.

**Не показывать** информацию «об игре»: описание, жанры и теги, разработчика, год, оценку, списки всех боссов и достижений, галереи скриншотов. Пользователь прямо сказал, что это ему не нужно. Арт игры (обложка, баннер, логотип) нужен только для оформления.

## Демо-игры

Сейчас в списке шесть пробных игр с `"demo": true`: Hollow Knight, Celeste, Elden Ring, Cyberpunk 2077, Silksong и Zelda TotK. Пользователь попросил их, чтобы посмотреть, как работает сайт. Их условия закрытия выдуманы для примера. Пока такие игры есть, на главной висит плашка «Демо-режим».

Когда пользователь пришлёт первую настоящую игру, нужно удалить все игры с `demo: true` вместе с `data/conditions/<id>.json`, `reports/<id>.md` и `themes/<id>/`, если только он не попросил оставить. Оформление удаляемой темы можно сначала перенести, если настоящая игра совпадает с демо.

## Структура

| Путь | Что это |
|---|---|
| `data/games.json` | Список игр: поле `updated` и массив `games` (только то, что нужно карточке и шапке) |
| `data/conditions/<id>.json` | Условия закрытия игры: группы, цели, статусы, картинки и заметки к целям |
| `reports/<id>.md` | Итоговый отчёт (Markdown) |
| `themes/<id>/` | Уникальное оформление игры: `theme.css`, `theme.js`, `assets.json`, `assets/` — см. `themes/README.md` |
| `index.html`, `assets/` | Сайт без сборки: список (`#/<вкладка>`) и страница игры (`#/game/<id>`); `assets/fx.js` — частицы |
| `scripts/import-conditions.js` | Импорт файла условий пользователя в `data/conditions/<id>.json` |
| `scripts/steam.js` | Поиск игры в Steam и арт для оформления (обложка, баннер, логотип) |
| `scripts/wiki.js` | Картинки и ссылки со статей вики — для иллюстраций к целям |
| `scripts/gen-image.py` | Генерация ассетов темы через OpenAI Images |
| `scripts/palette.py`, `scripts/fonts.js` | Палитра из арта и контраст; шрифты Google Fonts с кириллицей |
| `scripts/validate.js` | Проверка данных и тем; `--fix` пересчитывает счётчики целей, `--check-images` проверяет картинки и шрифты |

## Данные

### `data/games.json`

```json
{
  "id": "fire-emblem-engage",
  "title": "Fire Emblem Engage",
  "status": "in_progress",
  "platform": "Switch",
  "started": "2026-10-15",
  "finished": "2026-12-01",
  "playtime": 80,
  "priority": 1,
  "added": "2026-10-10",
  "notes": "Короткая заметка пользователя",
  "aliases": ["FE Engage"],
  "steamAppId": 367520,
  "cover": "https://…", "hero": "https://…", "logo": "https://…",
  "report": true,
  "goals": { "done": 12, "total": 30 },
  "theme": { "…": "см. «Оформление»" }
}
```

- Обязательные поля: `id` (kebab-case латиницей), `title` (оригинальное название), `status` (`in_progress`, `completed`, `planned` или `dropped`).
- Даты пишутся как `YYYY-MM-DD`, допустимы `YYYY-MM` и `YYYY`. «Сегодня» — это текущая дата сессии.
- `playtime` указывать, только если пользователь сам назвал часы. `priority` — место в очереди планов.
- `goals` — счётчик выполненных условий для карточки. Руками не править: его пересчитывает `node scripts/validate.js --fix`.
- `report: true` ставить, только если существует `reports/<id>.md`.

Создаётся импортом файла пользователя, затем дополняется иллюстрациями:

  "setup": ["Fire Emblem Engage (Switch), версия 2.0.0 + Expansion Pass", "Hard + Classic"],
  "groups": [
    {
      "title": "Сюжет",
      "note": "необязательная подпись группы",
      "goals": [
        {

          "gives": "Что нового даёт", "needs": "Что потребуется", "unlock": "Открывается", "counts": "Как засчитываем",
          "extra": [{ "label": "Другая колонка", "value": "…" }],
          "done": true, "date": "2026-11-30",
          "image": "https://…", "link": "https://…",

## Что делать на сообщения пользователя

- **Начинает игру и присылает условия закрытия** (путь к `.md` или текст):
  1. `node scripts/import-conditions.js "<файл>" <id>` (если прислан текст — сначала сохранить его в scratchpad). Импорт берёт «Цель», раздел «Игра», группы из «Конечного списка» (таблицы и чек-листы) и «Точку закрытия». Остальные разделы («Сознательно не делаем», «Источники»…) на сайт не идут.
  2. Запись в `games.json`: `status: in_progress`, `started`, `platform`, арт для оформления (`node scripts/steam.js search` → `info <appid>` → взять только `steamAppId`, `cover`, `hero`, `logo`; не из Steam — Википедия или вики игры, см. ниже).
  3. Каждой цели — картинку и ссылку (раздел «Иллюстрации к целям»).
  4. Уникальное оформление игры (раздел «Оформление»).
  5. `node scripts/validate.js --fix --check-images`, коммит, push.
- **«Выполнил #N» / «прошёл паралог X»** → у цели `done: true`, `date`; слова пользователя о ней — в `note`; подробности — в `details`. Если отмечен пункт чек-листа — `done` у пункта.
- **Прислал новую редакцию файла** (или файл с отметками ☑) → повторить импорт тем же `id`. Тексты и статусы обновятся, а картинки, ссылки, даты и заметки сохранятся. Импорт молча не снимает уже стоящие отметки.
- **Финальный отчёт** → текст в `reports/<id>.md` (см. «Отчёты»). Всё, что он говорит о конкретных целях, разнести по их `note`, `details` и `gallery`. Затем `status: completed`, `finished`, `playtime` (если назван). Все условия должны быть отмечены; если нет — уточнить у пользователя.
- **«Планирую X»** → `status: planned`, `added`, `priority`. Условия появятся, когда он пришлёт файл; до этого — только карточка с артом и оформлением.
- **«Бросил X»** → `status: dropped`, `finished` = дата; причину записать в `notes`.

Если игра уже есть — обновлять её, а не создавать новую. Ничего не засчитывать и не удалять из условий молча: список меняется только по прямому слову пользователя.

## Иллюстрации к целям

Каждая цель должна выглядеть как награда, а не как строка таблицы: нужны картинка, ссылка и, когда есть, детали.

- **Вики игры**: `node scripts/wiki.js <вики> "Статья 1" "Статья 2" …` даёт `image` и `link`. Если главная картинка статьи не подходит — `--images "<статья>"`. Для Fire Emblem это `fireemblemwiki.org/w`, для многих игр — `<игра>.fandom.com`. `*.wiki.gg` отвечает 401 на запросы скриптов: их не использовать.
- **Википедия**: `node scripts/wiki.js en.wikipedia.org/w --images "<статья>"`.
- **Steam** (арт, скриншоты, иконки достижений) — когда цель про то, что видно на скриншоте, или прямо про достижение.
- **Проверка**:
  - Скрипты проверяют, что по ссылке картинка, но не проверяют, та ли это картинка. Поле `query` в выводе `wiki.js` значит, что статья найдена поиском и может быть не той.
  - Сомнительные картинки смотреть глазами: собрать контактный лист PIL-ом в scratchpad и открыть Read.
  - Предупреждение валидатора «та же картинка, что у …» почти всегда означает заглушку вики.
- Ссылки — только прямые http(s) на файлы с CDN: `shared.akamai.steamstatic.com`, `static.wikia.nocookie.net`, `upload.wikimedia.org` и т.п. В `index.html` стоит `<meta name="referrer" content="no-referrer">` — без него Fandom отдаёт заглушку. Не удалять.

## Оформление: уникальный UI/UX/VFX для каждой игры

У каждой игры своё оформление, а не перекраска общего шаблона: своя раскладка условий закрытия, свой интерактив, свои эффекты, свой «вход» на страницу, своя карточка в списке. Эталон — `themes/hollow-knight/`: Дневник охотника вместо списка целей, сосуд души вместо кольца прогресса, светомуха-курсор, заставка области. API модулей и обязательные правила — в `themes/README.md`.

Порядок работы:

1. **Понять эстетику игры**: как выглядят её меню, журнал, инвентарь, карта, шрифты. Посмотреть `hero`, `logo` и скриншоты: скачать в scratchpad и открыть Read.
2. **Токены `theme` в `games.json`** — база для карточки и страницы:
   - Цвета `bg`, `surface`, `text`, `accent`, `accent2`. Палитру даёт `python -P scripts/palette.py <hero> <cover>`. Контраст текста ≥ 4.5, проверять через `--contrast`.
   - Шрифты Google Fonts в `fonts`, `displayFont`, `headingFont`, `bodyFont`. Для русского текста — только шрифты с кириллицей: `node scripts/fonts.js check` и `node scripts/fonts.js list --cyrillic`.
   - Остальное: `radius`, `ornament`, `particles` (embers, sparks, ash, snow, rain, spores, dust, stars, petals, leaves, bubbles), `textures` (vignette, grain, scanlines, glow, fog, paper, halftone), `heroPosition`.
   - `css: true` и `js: true` включают `themes/<id>/theme.css` и `themes/<id>/theme.js`.
3. **Модуль `themes/<id>/theme.js`**:
   - Раскладка условий в духе игры: журнал, инвентарь, карта восхождения, лог заданий, гобелен и т.п.
   - Индикатор прогресса в стиле игры.
   - Фирменный эффект: курсор, свет или частицы.
   - Заставка при входе на страницу.
4. **`themes/<id>/theme.css`**: стили модуля и карточки в списке. Карточка тоже должна быть узнаваемой: рамка, hover-эффект.
5. **Ассеты**: 3–6 оригинальных элементов (рамки, орнаменты, разделители, фоны, текстуры). Промпты записывать в `themes/<id>/assets.json`, генерировать командой `python -P scripts/gen-image.py --manifest themes/<id>/assets.json`. Без логотипов, текста и персонажей игры. Каждый ассет посмотреть глазами.
   - Ключ OpenAI — только из переменной окружения `OPENAI_API_KEY` или из файла вне репозитория (`--key-file`). Никогда не класть его в репозиторий: он публичный, а `.gitignore` закрывает только `*.key` и `.env*`. Если ключа нет — попросить у пользователя.
6. **Проверка в браузере**:
   - Страница игры и карточка, десктоп и 375 px, светлая и тёмная системная тема.
   - Клавиатура, `prefers-reduced-motion`, переход на другую игру и обратно (ничего не должно «протекать»), консоль без ошибок.
   - Модуль должен работать с любым набором целей: пустым, без картинок, с чек-листами, при любом статусе игры.

## Отчёты

Пользователь присылает отчёт своими словами.

- Сохранять **его текст и мнения**. Можно исправить опечатки, разбить на разделы (`reports/_template.md`), оформить списками. Ничего не выдумывать, оценок не добавлять.
- Заголовок с названием игры не нужен; файл начинается с `## …`.
- Можно вставить 1–3 иллюстрации: `![Подпись](https://…)`. Несколько картинок подряд на соседних строках становятся галереей.

## Публикация

После каждого обновления коммит и push в `main` делаются сразу, без вопроса: пользователь попросил держать сайт актуальным.

1. Обновить `updated` в `data/games.json`.
2. `node scripts/validate.js --fix --check-images` — должно быть `✓ OK`.
3. Коммит на русском: `Начато: Fire Emblem Engage (30 условий)`, `Fire Emblem Engage: выполнено #4–#6`, `Закрыто: Fire Emblem Engage`.
4. `git push`. GitHub Pages обновится примерно за минуту.
5. Коротко ответить пользователю: что изменилось и ссылка `https://dstratonov1234.github.io/completionist-list/#/game/<id>` (к конкретной цели — `…#/game/<id>` и номер цели).

## Локальный просмотр

`python -m http.server 8765` в корне репозитория (или конфигурация `site` в `.claude/launch.json`) и открыть http://localhost:8765. Открывать `index.html` напрямую как файл нельзя: `fetch` не работает с `file://`.
