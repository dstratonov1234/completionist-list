# Completionist List — инструкция для Claude

Личный трекер игр пользователя на GitHub Pages. Пользователь пишет в чате (по-русски), что начал, прошёл, бросил или планирует игру, а также присылает отчёты о прохождении. Задача Claude — поддерживать список в актуальном состоянии, **красиво оформлять каждую игру картинками и ссылками** и сразу публиковать изменения.

- Сайт: https://dstratonov1234.github.io/completionist-list/
- Репозиторий: https://github.com/dstratonov1234/completionist-list
- «Пройдено» здесь значит: игра закрыта полностью (100% / все ачивки / то, что пользователь считает финалом), возвращаться к ней он не будет.

## Структура

| Путь | Что это |
|---|---|
| `data/games.json` | Единственный источник данных: поле `updated` и массив `games` |
| `reports/<id>.md` | Отчёт о прохождении игры (Markdown), имя файла = `id` игры |
| `reports/_template.md` | Шаблон структуры отчёта |
| `index.html`, `assets/` | Статический сайт без сборки: список (`#/<вкладка>`) и страница игры (`#/game/<id>`) |
| `scripts/steam.js` | Поиск игры в Steam, арт/скриншоты/описание, достижения с иконками |
| `scripts/wiki.js` | Картинки и ссылки со статей вики (Fandom, wiki.gg, Википедия) — для боссов, концовок и т.п. |
| `scripts/validate.js` | Проверка данных; `--check-images` — проверка, что все картинки открываются |

Обязательные: `id` (kebab-case латиницей, уникальный), `title` (оригинальное название), `status`. Остальное — по ситуации; пустые поля не добавлять.

- `status`: `in_progress` | `completed` | `planned` | `dropped`.
- Даты: `YYYY-MM-DD`; если пользователь знает только месяц или год — `YYYY-MM` или `YYYY`. «Сегодня» = текущая дата сессии.
- `playtime` — часы. `rating` — 1–10. `progress` — проценты, только для `in_progress`. `priority` — порядок в планах (1 = следующая).
- `completion` — коротко, что закрыто (100%, платина, все ачивки, все концовки…). `achievements` — счётчик ачивок, если в игре они есть.
- `report: true` только если существует `reports/<id>.md`.
- Картинки: `cover` — горизонтальная обложка для карточки (вертикальный бокс-арт сайт сам покажет поверх размытой копии), `hero` — широкий баннер страницы игры, `logo` — логотип поверх баннера (если не грузится — показывается название текстом), `screenshots` — 4–8 штук для галереи.
- `goals` — то, что пользователь закрыл (или собирается закрыть). Типы и секции на странице: `boss` (Боссы), `ending` (Концовки), `challenge` (Испытания), `dlc` (Дополнения), `location` (Локации), `collectible` (Коллекции), `other` (Прочее) — карточки с большой картинкой; `achievement` (Достижения) — компактный список с иконкой и редкостью (`rarity` < 10% подсвечивается золотом). `done: false` — ещё не выполнено (показывается бледным). `note` — личный комментарий пользователя. `fit` (`cover`/`contain`) — только если автоматический выбор кадрирования выглядит плохо.

## Оформление: картинки и ссылки для каждой игры

Пользователь хочет, чтобы всё выглядело не сухим текстом, а красиво. Поэтому **любая игра, которая появляется в списке, сразу получает арт**, а пройденная — ещё и иллюстрированные цели.

### Новая игра (любой статус)

1. Steam: `node scripts/steam.js search "<название>"` → выбрать правильный appid (не саундтрек, не DLC, не демо) → `node scripts/steam.js info <appid>` → перенести в запись `steamAppId`, `cover`, `hero`, `logo`, `screenshots`, `description`, `developer`, `year`, `genres`, `links`.
2. Игры не из Steam (консоли, другие лаунчеры): обложка с Википедии — `node scripts/wiki.js en.wikipedia.org/w --images "<статья об игре>"` (там обычно есть `… cover.jpg` и скриншот геймплея); баннер и скриншоты — из вики игры на Fandom (`--images` по главной статье или по локациям). Ссылки: Википедия, вики игры, HowLongToBeat.
3. Добавить в `links` вики игры (Fandom / wiki.gg / Fextralife), если она есть.

### Пройденная игра / отчёт

Из отчёта пользователя выписать всё, что можно показать картинкой, и добавить в `goals`:

- **Боссы**, которых он упомянул (особенно сложных и финальных): `node scripts/wiki.js <вики> "Boss 1" "Boss 2" …` — даёт `image` и `link`. Названия статей на английских вики — на английском, `title` в goals — как назвал пользователь (или официальная русская локализация).
- **Концовки, испытания, DLC, коллекции, локации** — так же через вики.
- **Достижения**: `node scripts/steam.js achievements <appid> [фильтр]` — иконки, описания на русском и редкость. Если пользователь закрыл все ачивки — не вываливать весь список: взять 6–12 самых редких/значимых, а в `achievements` записать `{ done, total }`. Если упомянул конкретные — их обязательно.
- Личные фразы пользователя про конкретного босса/ачивку («убил с 40-й попытки») — в `note` этой цели, а не только в отчёт.

В сам отчёт можно вставлять картинки: `![Подпись](https://…)` — одна в абзаце станет иллюстрацией с подписью, несколько подряд (каждая на своей строке, без пустых строк между ними) — галереей. Все картинки на странице открываются по клику в полноэкранный просмотр.

### Проверка картинок — обязательно

- Скрипты сами проверяют, что URL отдаёт картинку, но **не проверяют, та ли это картинка**. Главная картинка статьи вики бывает общей заглушкой/промо-артом (у разных статей одна и та же). Если в выводе `wiki.js` есть поле `query` — статья найдена поиском и может оказаться не той (например, «Steel Soul» → статья про Silksong): такое не брать, искать точное название или `--images`.
- Сомнительные картинки посмотреть глазами: скачать в scratchpad (`curl -s -o <scratchpad>/x.png "<url>"`) и открыть Read'ом.
- Перед коммитом: `node scripts/validate.js --check-images`. Предупреждение «та же картинка, что у …» почти всегда значит заглушку — заменить.
- Только прямые http(s)-ссылки на файлы картинок с CDN (Steam: `shared.akamai.steamstatic.com`, `cdn.cloudflare.steamstatic.com`; Fandom: `static.wikia.nocookie.net`; Википедия: `upload.wikimedia.org`). Не ссылки на HTML-страницы.
- Fandom отдаёт заглушку, если видит чужой Referer, — поэтому в `index.html` стоит `<meta name="referrer" content="no-referrer">`. Не удалять.

## Что делать на типичные сообщения

- **«Начал X» / «прохожу X»** → `status: in_progress`, `started` = сегодня (или названная дата), арт по разделу выше. Если игра была в планах — убрать `priority` и пересчитать приоритеты остальных планов.
- **«Планирую X» / «хочу поиграть в X»** → `status: planned`, `added` = сегодня, `priority` = в конец очереди, если пользователь не сказал иначе; арт по разделу выше.
- **«Прошёл X» + отчёт** → `status: completed`, `finished`, `playtime`, `rating`, `completion`, `achievements` из отчёта; отчёт в `reports/<id>.md`, `report: true`; `goals` с картинками. Убрать `progress`.
- **«Прошёл X» без отчёта** → то же без файла; спросить про время, оценку и что закрыто, если не сказано. Отчёт можно добавить позже.
- **«Убил босса Y в X» / «выбил ачивку Z»** (игра в процессе) → добавить цель в `goals` с картинкой и датой.
- **«Бросил X»** → `status: dropped`, `finished` = дата, когда бросил; причину — в `notes`.
- **Прогресс / часы** («в X уже 40 часов, 60%») → обновить `playtime` / `progress` / `achievements`.

Если игра уже есть в списке — обновить существующую запись, а не создавать новую. Если название неоднозначно (ремастер, ремейк, серия) — уточнить у пользователя.

## Отчёты

Пользователь присылает отчёт своими словами. Сохранять **его текст и мнения**, а не переписывать их: можно исправить опечатки, разбить на разделы по `reports/_template.md` и оформить списками. Ничего не выдумывать — разделы, о которых он ничего не сказал, пропустить. Факты из отчёта (часы, оценка, что закрыто, даты) перенести в поля `games.json`. Заголовок с названием игры в отчёт не добавлять — сайт показывает его сам; начинать с `## …`. Можно добавить 1–3 иллюстрации к ключевым моментам (см. выше), но не превращать отчёт в галерею — для этого есть `goals` и `screenshots`.

## Публикация

После каждого обновления (пользователь попросил держать список актуальным — коммит и push в `main` делать сразу, без отдельного вопроса):

1. Обновить `updated` в `data/games.json` на сегодняшнюю дату.
2. `node scripts/validate.js --check-images` — должно быть `✓ OK`.
3. Коммит с понятным сообщением на русском, например `Пройдено: Hollow Knight`, `Начато: Elden Ring`, `В планы: Hades II`.
4. `git push` — GitHub Pages обновится примерно за минуту.
5. Ответить пользователю коротко: что изменилось, что добавлено из картинок (боссы, ачивки…) + ссылка на игру `https://dstratonov1234.github.io/completionist-list/#/game/<id>`.

## Локальный просмотр

`python -m http.server 8765` в корне репозитория (или конфигурация `site` в `.claude/launch.json`) и открыть http://localhost:8765. Открывать `index.html` напрямую из файла нельзя — `fetch` не работает с `file://`.
