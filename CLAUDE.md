# Completionist List — инструкция для Claude

Личный трекер **закрытия игр** пользователя на GitHub Pages. Пользователь пишет в чате по-русски. Когда он начинает игру, он присылает файл **«условия закрытия»** (`УСЛОВИЯ_ЗАКРЫТИЯ.md`) — свой нумерованный список целей, после которых игра считается закрытой навсегда. По ходу игры и в конце он присылает **отчёты** — свободный текст без формата; на сайт они не идут, по ним Claude сам отмечает выполненные условия. Задача Claude — вести эти данные, иллюстрировать каждую цель и оформлять каждую игру **своим уникальным UI/UX/VFX**. Изменения публикуются сразу.

- Сайт: https://dstratonov1234.github.io/completionist-list/
- Репозиторий: https://github.com/dstratonov1234/completionist-list (публичный)

## Главные правила

Всё это пользователь говорил прямо — не нарушать:

1. **Сайт — только про закрытие.** Страница игры показывает условия закрытия: какие выполнены, допинформацию к ним (картинка, что дало, как засчитано, подробности из отчётов, чек-листы) и прогресс. Больше ничего.
2. **Нигде не показывать:**
   - статус игры — «закрыта», «в процессе», «в планах», место в очереди (кроме названий категорий в списке на главной: статус и так виден по числу выполненных условий). В темах вместо статуса — прогресс по условиям;
   - даты — начала, закрытия, добавления, выполнения целей, «дней прохождения»;
   - заметки к игре (слоганы на баннере и под шапкой; поля `notes` нет);
   - брифинг файла условий — «цель закрытия», настройки прохождения, редакцию — и «точку закрытия» / «условие победы»;
   - отчёты пользователя;
   - информацию «об игре»: описание, жанры и теги, разработчика, год, оценку, платформу, списки всех боссов и достижений, галереи скриншотов. Арт игры (обложка, баннер, логотип) — только для оформления.
3. **Статуса «брошено» нет**: пользователь игры не бросает.
4. **Ничего не выдумывать за пользователя.** Цитата к цели (`note`), подпись группы, любые «его слова» — только из его файла, чата или отчёта. Ничего не засчитывать по догадке и не удалять из условий без его прямого слова.
5. **Каждая игра — полностью свой UI/UX/VFX, никакого общего каркаса сайта в новых цветах.** Тема игры сама строит **всё**, что видно про эту игру: баннер на главной (`banner`), фон главной при наведении (`stage`), всю страницу игры целиком — шапку, раскладку условий, прогресс, навигацию, кнопку «назад» (`page`) — и заставку при входе (`cover`), которая **плавно** начинается ещё на главной. Каждая часть задизайнена по мотивам интерфейса и мира именно этой игры; перекрасить общую разметку сайта шрифтом, рамкой и цветом — не считается. **Своя и компоновка:** нельзя повторять у разных игр один скелет — ни на странице («широкая полоса с артом сверху, под ней содержимое»), ни на баннере («арт во всю плашку, логотип слева, прогресс справа»), — у каждой игры своя композиция. Форма плашки и её выделение при наведении тоже свои (не «прямоугольник, у которого меняется цвет рамки»). В заставке — только название игры. Перед публикацией каждый новый или переделанный элемент оформления проходит **ревью на креативность и качество** — отдельным агентом-ревьюером (или самому по тем же вопросам, если правка мелкая), см. раздел «Ревью дизайна» в навыке. Как это делать — навык `game-theme` (`.claude/skills/game-theme/SKILL.md`), API — `themes/README.md`.
6. **Публиковать сразу**: после каждого изменения — коммит и push в `main` без вопроса.

## Главная

Тёмная и чистая — только поиск и список, без заголовка, статистики и вкладок. Список сверху вниз в сворачиваемых категориях «Закрытые» → «В процессе» → «В планах», внутри — по алфавиту. У каждой игры — свой баннер в стиле игры (логотип или название и прогресс по условиям). При наведении на баннер на главной происходит что-то своё для каждой игры — своя задумка, а не общий шаблон и не кусок страницы игры (у SMT V над главной собирается Магацухи и всходит луна, у Siralim открывается пиксельный портал в реалм). Клик — бесшовный переход: главная растворяется, поверх неё начинается заставка игры, страница игры открывается из-под неё.

## Условия закрытия

### Пользователь начинает игру и присылает файл условий

1. **Предобработка условий — сам Claude, по смыслу.** Прочитать файл целиком и самому перенести в `data/conditions/<id>.json` только **цели закрытия**:
   - группы и цели с номерами — как бы они ни были записаны (таблица, нумерованный пункт, список, чек-лист);
   - у цели — только её название словами пользователя (не переписывать), номер, чек-лист и уже стоящие отметки ☑ (+ дата, если она есть).

   **Колонки и пояснения к целям не переносить:** «Что нового даёт», «Что потребуется», «Открывается», «Как засчитываем», «Канон» и любые другие колонки, уточнения под пунктом, пояснения к группам — на сайте их нет (пользователь просил). «Как засчитываем» нужна только при разборе отчётов — её смотреть в самом файле пользователя.

   **Цель** — то, что можно однажды выполнить в игре и отметить: пройти, победить, сдать квест, сыграть. **Не цели**, даже если у них есть номер: общие требования ко всему прохождению («всё на Normal», «Casual не засчитывается»), ограничения и уточнения к другим целям, а также всё, что делается не в игре — «посмотреть концовки/бои в записи», «на видео»; их не переносить.

   **Не переносить** ничего, что не цель: шапку (цель закрытия, раздел «Игра», редакцию), «Сознательно не делаем», «Пропускаемое и порядок», «Защиту от затягивания», «Как засчитываем и ставим точку» / «Точку закрытия», источники, историю редакций, цены и покупки, служебные пометки вроде «(добавлено в редакции 4)». `scripts/import-conditions.js` — только черновик для таблиц: его результат всё равно сверить с файлом по каждой цели (он не видит, например, пояснений после таблицы).
2. **Запись в `games.json`:** `status: in_progress`, `started`, арт для оформления: `node scripts/steam.js search "<название>"` → `info <appid>` → взять только `steamAppId`, `cover`, `hero`, `logo`. Не из Steam — Википедия или вики игры.
3. **Иллюстрации** — каждой цели картинку и ссылку (ниже).
4. **Оформление** — по навыку `game-theme`: тема, баннер, заставка с переходом, ассеты, проверка в headless Chrome.
5. `node scripts/validate.js --fix --check-images`, коммит, push.

### Изменения

- **«Выполнил #N» / «прошёл паралог X»** → у цели `done: true`, `date`; его слова о ней — в `note`, подробности — в `details`; отмеченный пункт чек-листа — `done` у пункта.
- **Новая редакция файла** (или файл с отметками ☑) → так же самому перечитать и обновить JSON (черновик — импорт тем же `id`): тексты обновить, а у целей с тем же номером сохранить `image`, `link`, `date`, `note`, `details`, `gallery` и отметки — уже стоящие отметки молча не снимать. Убранные пользователем цели — убрать, новые — проиллюстрировать.
- **«Планирую X»** → `status: planned`, `added`, `priority`; баннер с артом и оформлением сразу, условия — когда пришлёт файл.
- Игра уже есть — обновлять её, а не создавать новую.

### Иллюстрации к целям

Каждая цель должна выглядеть как награда, а не как строка таблицы: картинка, ссылка и, когда есть, детали.

- **Вики игры:** `node scripts/wiki.js <вики> "Статья 1" "Статья 2" …` → `image` и `link`; если главная картинка статьи не подходит — `--images "<статья>"`. Fire Emblem — `fireemblemwiki.org/w`, многие игры — `<игра>.fandom.com`. `*.wiki.gg` — только для ссылок на статьи, картинки оттуда не брать: одни такие вики отвечают скриптам 401, другие после десятка запросов — 429 (rate limit), и на сайте картинки грузились бы ненадёжно.
- **Википедия:** `node scripts/wiki.js en.wikipedia.org/w --images "<статья>"`.
- **Steam** (арт, скриншоты, иконки достижений) — когда цель про то, что видно на скриншоте, или прямо про достижение.
- **Проверять глазами:** скрипты проверяют, что по ссылке картинка, но не что она та. Поле `query` в выводе `wiki.js` — статья найдена поиском и может быть не той. Сомнительные — контактный лист PIL-ом в scratchpad и Read. Предупреждение валидатора «та же картинка, что у …» почти всегда значит заглушку вики.
- Ссылки — только прямые http(s) на файлы с CDN (`shared.akamai.steamstatic.com`, `static.wikia.nocookie.net`, `upload.wikimedia.org`…). `<meta name="referrer" content="no-referrer">` в `index.html` не удалять — без него Fandom отдаёт заглушку.

## Отчёты

Пользователь присылает отчёты — промежуточные или финальный — **обычным текстом без формата**. Отчёт **не публикуется** и в репозитории не хранится (он публичный): это материал для Claude, чтобы закрывать условия.

1. **Сопоставить** написанное с условиями игры (`data/conditions/<id>.json`): какие цели и пункты чек-листов теперь выполнены. Названия у пользователя бывают неточными, по-русски или сокращённо — сопоставлять по смыслу.
2. **Засчитывать по формулировке «Как засчитываем»** — её смотреть в файле условий пользователя (на сайт она не переносится). Неясно, выполнено ли, — не отмечать молча, а спросить. Ничего «по догадке».
3. **Отметить:** целям — `done: true` и `date` (из отчёта, иначе дата отчёта; дата хранится только в данных), пунктам чек-листов — `done: true`.
4. **Допинформация** — коротко, своими словами, без пересказа отчёта: `details` (как закрыто: сложность, с какой попытки, чем запомнилось), `note` (одна меткая фраза самого пользователя, если она того стоит — не сочинять), `gallery` (картинки к моменту, если он описал что-то конкретное — через вики).
5. **Финальный отчёт:** закрыты все условия — `status: completed`, `finished`, `playtime` (если он назвал часы); чего-то не хватает — уточнить.
6. **Ответить** коротко: что отмечено (номера и названия), что осталось, ссылка на игру.

## Оформление

Каждой игре — свой UI/UX/VFX. Полная инструкция — навык **`game-theme`** (`.claude/skills/game-theme/SKILL.md`): эстетика, токены темы, модуль и баннер, заставка с бесшовным переходом (`cover()` + `ctx.handoff`), ассеты, проверка, подводные камни. API модуля и разметка страницы — `themes/README.md`. Образцы — темы демо-игр в истории git (см. ниже).

**Ключ OpenAI** для ассетов: пользователь разрешил тратить его на темы. Лежит вне репозитория в `~/.config/completionist-list/openai.key`, `scripts/gen-image.py` берёт его сам. Никогда не печатать и не коммитить (репозиторий публичный, `.gitignore` закрывает только `*.key` и `.env*`); перед коммитом — `git diff --cached | grep -cE "sk-[A-Za-z0-9_-]{20,}"` должно быть 0. Ключа нет — попросить у пользователя.

## Демо-игры (удалены)

Семь пробных игр (Hollow Knight, Celeste, Elden Ring, Cyberpunk 2077, Silksong, Zelda TotK, Fire Emblem Engage) пользователь попросил, чтобы посмотреть, как работает сайт, и 2026-10-15 попросил удалить. Их темы остались в истории git на коммите `6522181` — это готовые образцы модулей, баннеров и заставок с переходом: `git show 6522181:themes/hollow-knight/theme.js` (эталон), `git ls-tree -r --name-only 6522181 themes/`. Если пользователь начнёт одну из этих игр по-настоящему, оформление можно вернуть оттуда (`git checkout 6522181 -- themes/<id>`) и доработать, а условия — только из его нового файла. Его настоящий файл условий Fire Emblem Engage — `D:\FireEmblemEngage\УСЛОВИЯ_ЗАКРЫТИЯ.md`. Поле `"demo": true` в `games.json` (метка «демо» в шапке) — только для пробных игр.

## Структура

| Путь | Что это |
|---|---|
| `data/games.json` | `updated`, `build` и массив `games` (только то, что нужно баннеру и шапке) |
| `data/conditions/<id>.json` | Условия закрытия игры: группы, цели, отметки, картинки, допинформация |
| `themes/<id>/` | Оформление игры: `theme.css`, `theme.js`, `assets.json`, `assets/` |
| `index.html`, `assets/` | Сайт без сборки: список (`#/`) и страница игры (`#/game/<id>`); `assets/app.js` — движок, `assets/fx.js` — частицы |
| `.claude/skills/game-theme/` | Навык: как делать оформление игры |
| `scripts/import-conditions.js` | Импорт файла условий в `data/conditions/<id>.json` |
| `scripts/steam.js`, `scripts/wiki.js` | Арт из Steam; картинки и ссылки со статей вики |
| `scripts/gen-image.py` | Ассеты темы через OpenAI Images |
| `scripts/palette.py`, `scripts/fonts.js` | Палитра из арта и контраст; шрифты Google Fonts с кириллицей |
| `scripts/shots.mjs`, `scripts/check-entrances.py` | Headless Chrome: скриншоты/скринкаст сценариев; сквозная проверка входа во все игры |
| `scripts/validate.js` | Проверка данных и тем; `--fix` пересчитывает счётчики и `build`, `--check-images` проверяет картинки и шрифты |

## Данные

### `data/games.json`

```json
{
  "id": "fire-emblem-engage",
  "title": "Fire Emblem Engage",
  "status": "in_progress",
  "started": "2026-10-15",
  "finished": "2026-12-01",
  "playtime": 80,
  "priority": 1,
  "added": "2026-10-10",
  "aliases": ["FE Engage"],
  "steamAppId": 367520,
  "cover": "https://…", "hero": "https://…", "logo": "https://…",
  "goals": { "done": 12, "total": 30 },
  "theme": { "…": "токены оформления — см. навык game-theme" }
}
```

- Обязательные поля: `id` (kebab-case латиницей), `title` (оригинальное название), `status` (`completed`, `in_progress` или `planned`).
- Даты — `YYYY-MM-DD` (допустимы `YYYY-MM` и `YYYY`); «сегодня» — текущая дата сессии. `started`, `finished`, `added` и `date` у целей — только запись в данных, на сайте их нет.
- `playtime` — только если пользователь сам назвал часы. `priority` — место в очереди планов (на сайте не показывается).
- `goals` и `build` руками не править: `node scripts/validate.js --fix` пересчитывает счётчик целей и ставит `build` — хэш кода сайта — в `games.json` и в ссылки `?v=` в `index.html`, чтобы после публикации браузер не брал старые файлы из кэша.

## Публикация

После каждого обновления — сразу, без вопроса:

1. Обновить `updated` в `data/games.json`.
2. `node scripts/validate.js --fix --check-images` — должно быть `✓ OK` (заодно обновит `build`).
3. Проверить, что ключа нет в изменениях: `git diff --cached | grep -cE "sk-[A-Za-z0-9_-]{20,}"` → 0.
4. Коммит на русском: `Начато: Fire Emblem Engage (30 условий)`, `Fire Emblem Engage: выполнено #4–#6`, `Закрыто: Fire Emblem Engage`.
5. `git push`. GitHub Pages обновится примерно за минуту.
6. Коротко ответить пользователю: что изменилось и ссылка `https://dstratonov1234.github.io/completionist-list/#/game/<id>`.

## Локальный просмотр и проверка

- Сервер: `python -m http.server 8765` в корне (или конфигурация `site` в `.claude/launch.json`), открыть http://localhost:8765. `index.html` как файл не открывать — `fetch` не работает с `file://`.
- Встроенный браузер, когда его панель скрыта, замораживает анимации — заставки и переходы проверять в headless Chrome: `python -P scripts/check-entrances.py <scratchpad>/<папка>` и `node scripts/shots.mjs …` (подробности — в навыке `game-theme`).
