# Completionist List — инструкция для Claude

Личный трекер игр пользователя на GitHub Pages. Пользователь пишет в чате (по-русски), что начал, прошёл, бросил или планирует игру, а также присылает отчёты о прохождении. Задача Claude — поддерживать список в актуальном состоянии и сразу публиковать изменения.

- Сайт: https://dstratonov1234.github.io/completionist-list/
- Репозиторий: https://github.com/dstratonov1234/completionist-list
- «Пройдено» здесь значит: игра закрыта полностью (100% / все ачивки / то, что пользователь считает финалом), возвращаться к ней он не будет.

## Структура

| Путь | Что это |
|---|---|
| `data/games.json` | Единственный источник данных: поле `updated` и массив `games` |
| `reports/<id>.md` | Отчёт о прохождении игры (Markdown), имя файла = `id` игры |
| `reports/_template.md` | Шаблон структуры отчёта |
| `index.html`, `assets/` | Статический сайт (без сборки), читает `games.json` и отчёты через `fetch` |
| `scripts/validate.js` | Проверка данных: `node scripts/validate.js` |

## Поля игры

```json
{
  "id": "hollow-knight",
  "title": "Hollow Knight",
  "status": "completed",
  "platform": "PC",
  "steamAppId": 367520,
  "cover": "https://…/header.jpg",
  "started": "2026-08-01",
  "finished": "2026-09-20",
  "playtime": 64,
  "rating": 10,
  "completion": "112%, все 63 достижения",
  "progress": 35,
  "priority": 1,
  "added": "2026-10-15",
  "notes": "Короткая заметка",
  "aliases": ["HK", "Холлоу Найт"],
  "report": true
}
```

Обязательные: `id` (kebab-case латиницей, уникальный), `title` (оригинальное название), `status`. Остальное — по ситуации, пустые поля просто не добавлять.

- `status`: `in_progress` | `completed` | `planned` | `dropped`.
- Даты: `YYYY-MM-DD`; если пользователь знает только месяц или год — `YYYY-MM` или `YYYY`. «Сегодня» = текущая дата сессии.
- `playtime` — часы (число, можно дробное). `rating` — 1–10. `progress` — проценты, только для `in_progress`. `priority` — порядок в планах (1 = следующая).
- `completion` — коротко, что именно закрыто (100%, платина, все ачивки, все концовки…).
- `report: true` только если существует `reports/<id>.md`.

## Что делать на типичные сообщения

- **«Начал X» / «прохожу X»** → `status: in_progress`, `started` = сегодня (или названная дата). Если игра была в планах — убрать `priority` и пересчитать приоритеты остальных планов.
- **«Планирую X» / «хочу поиграть в X»** → `status: planned`, `added` = сегодня, `priority` = в конец очереди, если пользователь не сказал иначе.
- **«Прошёл X» + отчёт** → `status: completed`, `finished`, `playtime`, `rating`, `completion` из отчёта; отчёт сохранить в `reports/<id>.md`, поставить `report: true`. Убрать `progress`.
- **«Прошёл X» без отчёта** → то же, но без файла; спросить про время, оценку и что закрыто, если не сказано. Отчёт можно добавить позже.
- **«Бросил X»** → `status: dropped`, `finished` = дата, когда бросил; причину — в `notes`.
- **Прогресс / часы** («в X уже 40 часов, 60%») → обновить `playtime` / `progress`.

Если игра уже есть в списке — обновить существующую запись, а не создавать новую. Если название неоднозначно (ремастер, ремейк, серия) — уточнить у пользователя.

## Обложки

Для игр из Steam: найти appid и взять точную обложку из API:

```
curl -s "https://store.steampowered.com/api/appdetails?appids=<APPID>&filters=basic"
```

Записать `steamAppId` и `cover` = значение `header_image` (можно без `?t=…`). Без `cover` сайт сам подставит `https://cdn.cloudflare.steamstatic.com/steam/apps/<APPID>/header.jpg`. Для игр не из Steam (консольные эксклюзивы и т.п.) можно указать любую прямую ссылку на горизонтальную картинку ~460×215 или ничего — тогда сайт нарисует цветную плашку с инициалами.

## Отчёты

Пользователь присылает отчёт своими словами. Сохранять **его текст и мнения**, а не переписывать их: можно исправить опечатки, разбить на разделы по `reports/_template.md` и оформить списками. Ничего не выдумывать — разделы, о которых он ничего не сказал, пропустить. Факты из отчёта (часы, оценка, что закрыто, даты) перенести в поля `games.json`. Заголовок с названием игры в отчёт не добавлять — сайт показывает его сам; начинать с `## …`.

## Публикация

После каждого обновления (пользователь попросил держать список актуальным — коммит и push в `main` делать сразу, без отдельного вопроса):

1. Обновить `updated` в `data/games.json` на сегодняшнюю дату.
2. `node scripts/validate.js` — должно быть `✓ OK`.
3. Коммит с понятным сообщением на русском, например `Пройдено: Hollow Knight`, `Начато: Elden Ring`, `В планы: Hades II`.
4. `git push` — GitHub Pages обновится примерно за минуту.
5. Ответить пользователю коротко: что изменилось + ссылка на игру `https://dstratonov1234.github.io/completionist-list/#/game/<id>`.

## Локальный просмотр

`python -m http.server 8765` в корне репозитория (или конфигурация `site` в `.claude/launch.json`) и открыть http://localhost:8765. Открывать `index.html` напрямую из файла нельзя — `fetch` не работает с `file://`.
