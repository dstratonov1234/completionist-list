# Темы игр: свой UI/UX/VFX для каждой игры

Каждая игра оформляется не перекраской, а собственным дизайном: своя раскладка секций, свои интерактивные элементы, свои эффекты и сгенерированные ассеты. Эталон — `hollow-knight/`.

```
themes/<id>/
  theme.css     — стили баннера на главной и страницы игры (грузится сразу, если theme.css: true)
  theme.js      — модуль страницы: перестраивает разметку, добавляет VFX и интерактив (theme.js: true)
  assets.json   — промпты сгенерированных ассетов (чтобы можно было перегенерировать)
  assets/*.webp — сами ассеты
```

Флаги `css` и `js` ставятся в `theme` игры в `data/games.json`. Цвета, шрифты, частицы и текстуры из `theme` продолжают работать — модуль строится поверх них.

## theme.css

- Селекторы **только** с префиксом игры: `.gbanner[data-game="<id>"] …` (баннер на главной), `.stage-layer[data-game="<id>"] …` (фон главной при наведении) и `html[data-game="<id>"] …` (страница). Классы, которые добавляет модуль, — с коротким префиксом игры (`hk-`, `er-`, `cp-`…), чтобы не пересечься с другими.
- Пути к ассетам относительные: `url(assets/frame.webp)`.
- **Баннер на главной** (только CSS — theme.js на главной не работает): `<a class="gbanner <status> themed-card [has-logo]" data-game="<id>">` → `.gb-media img` (арт, `::after` — градиент для читаемости) → `.gb-body` (сетка: `.gb-main` | `.gb-progress`) → `.gb-title` (`.gb-logo`, `.gb-name` — скрыт, пока виден логотип), `.gb-notes`, `.gb-progress` (`.gb-count b/span`, `.gb-label`, `.progress`). У `.gbanner` свободны `::before` и `::after`. Высота и раскладка — общие для всех, чтобы список читался как одна система; свечение при наведении — в пределах ~10 px.
- **Сцена** (`#stage`): при наведении на баннер фон главной становится `.stage-layer[data-game="<id>"]` — копией верха страницы игры (`.stage-hero`: баннер-арт + тот же градиент на фоне темы). По клику главная растворяется, страница игры проявляется поверх того же кадра, а затем идёт заставка игры (её не трогать — пользователь их любит). Если у страницы с самого начала постоянно видно что-то поверх/под баннером (не разовая заставка) — повторить это CSS-ом на `.stage-layer[data-game="<id>"]`, иначе переход «прыгнет».

## theme.js

```js
GameThemes.register("<id>", {
  page(ctx) {
    // вызывается после отрисовки стандартной страницы игры
    return () => { /* необязательная своя уборка */ };
  },
});
```

`ctx`:

| Поле | Что это |
|---|---|
| `game` | запись игры из games.json |
| `root` | `#game-view` — вся страница игры |
| `el.hero`, `el.heroTitle`, `el.layout`, `el.main`, `el.side` | основные части страницы |
| `conditions` | условия закрытия из `data/conditions/<id>.json` (или `null`, если их ещё нет): `{ title, groups[{ title, note, goals[] }] }` |
| `goals()` | все цели плоским списком; цель: `{ n, title, gives?, needs?, unlock?, counts?, extra?[{label,value}], done, date?, image?, link?, note?, details?, gallery?[], checklist?[{ label?, items[{ title, done }] }] }` |
| `groups()` | DOM-элементы групп: `<section class="block cond-group" data-section="group" data-group="<i>">` |
| `goalEl(n)` | DOM-элемент цели: `<article class="cond done|todo" data-goal="<n>" id="goal-<n>">` |
| `section(key)` | прочие секции страницы по `data-section` (сейчас таких нет — `null`) |
| `reportReady` | устарело: отчёты на сайт не выводятся, всегда уже выполненный Promise |
| `assets` | `"themes/<id>/assets/"` |
| `reducedMotion`, `finePointer` | `prefers-reduced-motion` и наличие мыши (на телефоне hover нет) |
| `listen(target, type, fn, opts)` | addEventListener, который сам снимется при уходе со страницы |
| `loop(fn(now, dt))` | requestAnimationFrame-цикл, сам остановится |
| `layer(className, parent?)` | `<div>` (по умолчанию в `body`), сам удалится — для оверлеев, курсоров, фонов |
| `onCleanup(fn)` | любая своя уборка (таймеры и т.п.) |
| `esc`, `safeUrl`, `fmtHours`, `plural` | хелперы сайта |
| `fx` | `GameFX` — частицы (`fx.start({type, color, density})`) |

Пока модуль грузится, стандартная раскладка скрыта (`.module-pending`), так что перестройка не мигает. Лайтбокс работает для любых `img[data-zoom]` внутри контейнера с `data-gallery`.

## Заставка через переход: `cover()` + `ctx.handoff`

Чтобы вход с главной был бесшовным, заставка игры начинается ещё на главной:

```js
GameThemes.register("<id>", {
  // по клику на баннер, на главной: закрыть экран своей заставкой (занавес, тучи, вуаль…), вернуть Promise,
  // который выполнится, когда экран закрыт полностью. Слои — только через t.layer().
  cover(t) { const c = t.layer("xx-curtain"); /* анимация закрытия */ return t.wait(600); },
  page(ctx) {
    // ctx.handoff = { layers, data } — если пришли с главной через cover(): слои уже закрывают экран,
    // нужно сыграть открытие и убрать их. ctx.handoff = null — страница открыта напрямую: обычная заставка.
  },
});
```

`t` (контекст `cover`): `game` (запись из games.json, в т.ч. `goals: {done,total}`), `assets`, `esc`, `finePointer`, `data` (объект, который увидит `ctx.handoff.data`), `layer(className)` (элемент в `body`, переживает переход; на нём уже стоят переменные темы `--t-display`, `--t-accent`… — на главной их больше нигде нет), `wait(ms)`. Модуль на главной предзагружается при наведении на баннер. Пока идёт `cover()`, главная растворяется; страница игры собирается под закрытым экраном. Незабранные слои движок уберёт через 6 с. При `prefers-reduced-motion` `cover()` не вызывается. Эталон — `themes/hollow-knight/theme.js` (вуаль и карточка области).

## Что на странице игры

Страница — **только про условия закрытия**, которые пользователь сам себе поставил, прогресс по ним. Отчёты пользователя на сайт не выводятся; брифинга («цель закрытия», настройки, редакция) и «точки закрытия» на странице тоже нет — пользователь просил не мусорить. **Статус игры не называть нигде** (ни на баннере, ни на странице, ни в заставке: «закрыто», «в процессе», «в планах», очередь) — вместо него прогресс по условиям; класс статуса у `.gbanner`/`.hero` можно использовать только для оформления (цвет, свечение), без надписей. **Дат на сайте нет** — ни у игры, ни у целей. Не показывать «об игре»: описание, жанры/теги, разработчика, оценку, списки всех боссов/достижений, галерею скриншотов.

Стандартная разметка (её модуль перестраивает как хочет): шапка-баннер (`.hero`) → заметка `.game-notes` → группы `.cond-group` с целями `.cond` (картинка `.cond-media`, номер `.cond-num`, `.cond-title`, `.cond-state`, факты `.cond-facts` «Что даёт / Что потребуется / Открывается / Как засчитываем», чек-лист `.cond-check`, заметка пользователя `.cond-note`, ссылка `.cond-link`) → соседние игры. Сбоку `.game-side`: кольцо прогресса `.ring`, прогресс по группам `.group-progress` (ссылки `[data-jump]` прокручивают к группе), время в игре (если пользователь его назвал).

## Обязательные правила

- **Данные — только из `ctx.game` / `ctx.conditions` / `ctx.goals()`**: тема одна на игру, но цели и цифры меняются. Ничего не захардкоживать (названия целей, числа) — модуль должен работать при любом наборе целей и групп, с картинками и без, с чек-листами и без, а также когда условий ещё нет (`ctx.conditions === null`).
- Выполненные цели — главное: они должны выглядеть как награда; невыполненные — понятно, но приглушённо.
- **Всё через ctx** (`listen`, `loop`, `layer`, `onCleanup`) — после ухода со страницы не должно остаться слушателей, циклов и элементов.
- **Доступность и устройства**: интерактив работает с клавиатуры и тапом (hover — только как дополнение); при `ctx.reducedMotion` — без анимаций и курсорных эффектов; на ширине 375 px нет горизонтального скролла, текст читается.
- **Производительность**: не больше одного своего rAF-цикла, анимировать `transform`/`opacity`, не вешать `box-shadow`/`filter` на сотни элементов.
- **Безопасность**: текст из данных вставлять только через `ctx.esc`, ссылки — через `ctx.safeUrl`.
- **Ассеты**: генерировать `python -P scripts/gen-image.py --manifest themes/<id>/assets.json --key-file <ключ вне репозитория>`; ключ никогда не класть в репозиторий. Промпты — оригинальные элементы интерфейса «в духе» игры: орнаменты, рамки, разделители, фоны, текстуры, иконки. **Без логотипов, без текста и без персонажей игры** (их арт берётся из Steam/вики). Обычно 3–6 ассетов, каждый ≤ 300 КБ (`max_width`). Прозрачные поля обрезаются сами; для рамки из углов — `"mirror": true`.
- Проверить в браузере: баннер на главной и фон при наведении, вход в игру по клику (бесшовно, заставка игры играет) и обратно, страница игры, десктоп и 375 px, переход на другую игру и обратно (ничего не должно «протекать»), консоль без ошибок.
